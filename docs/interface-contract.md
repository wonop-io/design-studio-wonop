# Native interface contract

Parent integration owns the shared backend and manifest; UI uses the existing Design Bench `useArtifacts` hook, transfer/recovery owners, template compiler and native bridge. No browser mocks or separate domain/persistence services. Package id `design-studio`, name Design Studio. Four stages: directions, artboard, component-board image, working component HTML (`components` kind with html/legacyScreen). No documentation or full build stop. `benchGenerate` on approved artboard derives components directly; `format:html` converts approved component board; a note revises the current artifact. `benchOpen` keeps the same project window. New windows get distinct input-root families. Parent implements native scoping before exposing state.

## Existing native commands/messages

Keep canonical `bench*` and `publishBuild` signatures (see design-bench manifest). `benchState`/benchState messages return workspace.nodes and selected scoped to this window's project; normal runs/inputRecovery/storageError/stopReceipts remain. Native `benchApprove` and `benchReview` page messages remain human-only and exact-artifact/hash-bound. UI starts `startTemplateRenderer()` for native validation and shows real errors when outside Wonop. The app has one native tab per host; create other projects via `studioNewWindow`, not a project picker.

Additional `workspace.studio` = `{projectId, preferences:{reviewer,autoAdvance}, drafts:Record<artifactId+':'+kind,{text,selection?}>, captures:Record<artifactId,Capture>, feedback:Array<Feedback & {runId:string}>}`. These are acknowledged metadata on the canonical graph/checkpoint owner, not another browser store. Input editing reuses existing hook recovery.

## Studio adapter commands

- `studioNewWindow({})` → native `{windowId,hostId}`; no hostId means a new native window. Native opening binds a fresh input family.
- `studioPreferences({reviewer?:string,autoAdvance?:boolean})` → acknowledged preferences. Auto-advance only navigates after actual human approval.
- `studioDraft({artifactId,kind:'instruction'|'selection',text,selection?:object})` → acknowledged draft. Selection stores normalized region/reveal, not PNG data. Preserve on failures; clear only after acknowledged successful action.
- `studioExport({})` → native `{saved:boolean}` for the current project's JSON manifest. Preserve cancellation/failure truth.
- `studioCapture({artifactId,contentHash,imageId,width,height,theme:'light'|'dark'})` → `Capture`. Stage the PNG with `benchStageInput` first. The backend checks current raw HTML content hash, exact component-board source and owned PNG metadata; no AI/model call is made. `Capture` has `id,artifactId,contentHash,artifactHash,sourceId,sourceHash,imageId,width,height,theme,created`.
- `studioEvidence({artifactId,feedbackId?:string,imageId?:string})` → `{capture?:Capture,feedback?:object,image?:{id,mime,dataUrl}}`. Current capture when feedbackId omitted; omitting imageId returns its PNG. Read capture metadata without bytes from `benchState().workspace.studio.captures[artifactId]`. Read one owned requested image at a time. Source board content stays on `benchContent({artifactId:sourceId})`.
- `studioFeedback({artifactId,captureId,operationId,comment?:string,area:{x,y,width,height},bounds:{x,y,width,height,totalWidth,totalHeight},images:{artwork:string,ui:string,difference:string},builder:'codex'|'claude',builderWindowId})` → `{run,feedback}`. Stage each PNG separately with benchStageInput; pass owned asset IDs. Area is normalized to the comparison canvas; bounds are integer comparison pixels. One stable operationId per send attempt; preserve it across uncertain reply/retry. Backend persists evidence and uses the existing native generation/refinement run; duplicate identical operation replays its run. Run/receipt does not mean completion. Resulting HTML is a sibling draft through publishBuild.

## Capture and comparison

Read fresh raw HTML/hash with benchContent and compile through existing renderTemplate. Capture that exact compiled HTML in an isolated `sandbox=allow-scripts` frame using existing vendored modern-screenshot; channel/source-match all messages. No allow-same-origin, wm access, screen permission, fake render, filters or provider call. Await fonts/images, preserve actual DOM state and report capture failure; never compare a stale capture as current. Canonical raw contentHash is distinct from artifact approvalHash. On new published artifact/hash, invalidate/refresh capture. Capture records actual width/height/theme; original artboard retains original colors. Both PNG crops and difference must use the same width-coordinate grid and include any height mismatch. The UI promotes the existing PoC comparison algorithm into production ownership; no runtime/build imports from poc.

On Send, include all three real PNGs and optional comment. Native backend saves accessible evidence files through built-in app.ai.image.save with truthful non-generated provenance before coding dispatch, so agents can inspect them as files as well as through studioEvidence. No invented delivery/completion states. The Agent pane uses native session selection/opener and actual run states, cancellation/retry/recovery. Do not add a second receipt ledger or agent runtime.
